## System and threat model

An arbitrary caller can compose raw groups, choose ABI arguments, make public reads, deploy another app, and register its own funded data. A plugin delegate has only the wallet grant and immutable namespace/key scope actually installed. An owner or authorized delegate may race another authorized writer. RPC responses may be lost after transactions confirm.

| Surface | Authority and state transition | Audit result |
| --- | --- | --- |
| `create`, lifecycle | Creation initializes registry permission or immutable plugin scope; generated routers reject update/delete | Confirmed in generated programs; deployment identity remains a consumer trust assumption |
| `setRecord`, `removeRecord` | Only `Txn.sender`'s full-address key; expected revision required | Owner isolation holds; absent-state generation issue is ALG-01 |
| `beginRecord`, `appendRecord`, `commitRecord`, `cancelRecord` | Owner-keyed `u/w`; ID, offset, completeness, scope checked; commit publishes atomically | Tested; ALG-01 and ALG-03 affect concurrency/recovery |
| New-record payments/refunds | Adjacent same-sender exact payment, no payment close/rekey; refund to owner; inner fees zero | Formula and LocalNet balance conservation agree |
| MetaPlugin write methods | Fixed registry/scope; spending address read from wallet; wallet validates actual method selectors and wallet argument | Raw bypass attempts rejected; failed restoration rolls back |
| Legacy roots/data/types | Sender-owned roots; preserved `t/r/d`; fixed 100 ALGO type registration | ABI/layout preserved; inherited encoding and fee caveats below |
| Reads/discovery | Public raw boxes and foreign reads; family writes disabled | Tested for unrelated and same-creator consumers; SDK filters `m` names |

Security-critical owner identity is enforced by the registry, not supplied as a write argument. New keys use full 32-byte addresses and a namespace length byte, so concatenation cannot make `("ab","c")` collide with `("a","bc")`. The combined 30-byte name bound makes the complete box name at most 64 bytes. The analogous Merkle **leaf** encoding does not have that boundary protection.

## ALG-01: absent-key drafts can survive newer publication and deletion

- Severity: **Medium**. Confidence: **High**. Status: **Open**.
- Primary locations: [absent revision returns zero](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/smart_contracts/meta/contract.algo.ts:517), [commit revision comparison](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/smart_contracts/meta/contract.algo.ts:619), [deletion removes the revision header](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/smart_contracts/meta/contract.algo.ts:648).

**Violated invariant.** A draft whose base state was superseded must not later become eligible to publish. Registry-wide revision numbers protect existing records, but every absent state is represented by zero and deleting a record leaves its draft intact.

**Reproduction.** Begin and finish uploading draft A with `expectedRevision = 0` while the key is absent. Another authorized operation publishes B at that key, then deletes B using B's correct revision. Commit A. The expected and current revisions now both equal zero, so A publishes successfully with a new global revision. The global counter increment on deletion does not participate in this comparison.

**Impact and conditions.** Two owner sessions, or two delegates authorized for the same key, can unintentionally resurrect old content after the newer value was deliberately deleted. This is a concurrency/integrity failure, not authority to write another owner's key. An unsigned outsider cannot use it. The existing stale-draft test begins from a nonzero revision and therefore misses this path.

**Evidence.** `ALG-01` in [the LocalNet reproducer](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/tests/meta-audit.e2e.spec.ts:45) observes deletion, then successful stale publication with the old byte value. This contradicts the documentation's claim that a concurrent small write or deletion invalidates the draft.

**Recommended fix.** Invalidate or cancel the affected draft on a conflicting successful publication/deletion, while keeping its deposit recoverable. Alternatively, maintain a per-key generation that survives absence. A tombstone would change full-delete refund semantics; account for that explicitly. Do not merely reuse zero as an invalid marker, because deletion makes zero current again. A registry-wide generation check on every draft would unnecessarily conflict unrelated keys. If the intended policy only compares whether the key is currently absent and permits this sequence, explicitly adopt that weaker policy and correct the documented draft-invalidation guarantee.

**Regression test.** The reproduced sequence must reject A's commit and leave the key absent. Also cover absent → create → delete → recreate, cancellation/refund of the invalidated draft, and unrelated-key writes that should remain nonconflicting.

## ALG-02: ambiguous dynamic-field Merkle leaf encoding

- Severity: **Medium**. Confidence: **High**. Status: **Open; inherited**.
- Primary locations: [raw string encoding](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/tree.ts:157), [field concatenation](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/tree.ts:185).
- Related: [legacy re-export](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta-merkles/tree.ts:1), [registry proof verification](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/smart_contracts/meta/contract.algo.ts:315).

**Violated invariant.** Different values under the same supported tuple schema must have different encoded leaf preimages, absent a cryptographic collision. Each string is encoded as raw UTF-8, then fields are concatenated without lengths.

**Reproduction.** Under `[SchemaPart.String, SchemaPart.String]`, `['alice', 'admin']` and `['alicead', 'min']` both encode to `aliceadmin`. They have identical double-SHA256 leaf hashes. A tree containing only the first tuple accepts a proof for the second tuple. The LocalNet reproduction registers this schema and confirms that Meta's `verify` returns true using the substituted tuple's leaf and the original proof.

**Impact and conditions.** A consumer that uses this SDK encoding to prove structured claims containing multiple variable-length strings can accept a tuple the root author never included. For example, a `(tenant, resourceName)` authorization list can accept a different tenant/resource pair when both shifted strings are valid identifiers. This requires a schema/consumer with that ambiguity; the current fixed-width address and uint64 helper use cases are unaffected. The contract receives a hash and cannot recover the intended field boundaries. Type checking does not help because both tuples use the same registered type. No deployed consumer exploit is claimed.

**Evidence.** `ALG-02` in [the SDK tests](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/audit.test.ts:9) and [the LocalNet tests](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/tests/meta-audit.e2e.spec.ts:96). The same encoding is present in the pre-consolidation source at the reviewed base commit; this was preserved, not introduced by the rename.

**Recommended fix.** Introduce an explicitly versioned unambiguous tuple encoding, such as length-delimited strings or a specified ARC-4 tuple encoding, and use it consistently in producers and verifiers. Do not silently change the existing encoder: that would invalidate legacy roots and consumers. Until a new encoding is adopted, reject ambiguous schemas for new roots or clearly expose the old encoder as a compatibility mode with its restrictions.

**Regression test.** The two tuples must produce different leaves under the new encoding and a substituted proof must fail. Preserve test vectors for the existing fixed-width and explicitly legacy encodings.

## ALG-03: upload-start response loss bypasses recovery

- Severity: **Low**. Confidence: **High**. Status: **Open**.
- Locations: [MetaSDK start occurs outside the catch](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/index.ts:581), [MetaPluginSDK has the same ordering](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/wallet/plugins/meta.ts:308).

**Violated invariant.** After a possibly committed upload start, callers must be able to determine the outcome and recover the reserved draft. Both helpers generate a private upload ID and await `beginRecord`/`beginSet` before entering the `try` that cancels failed uploads. Neither exposes a recovery handle on failure.

**Reproduction.** Wrap `client.send.beginRecord` so it submits and confirms normally, then throws a simulated lost-response error. `setRecord` rejects, no published value exists, and a fresh `setRecord` immediately fails with `META_UPLOAD_EXISTS`. The reserved deposit remains. The reproduction retrieves the ID from the `w` state via the generated accessor and manually cancels, recovering the complete deposit. SDK tests confirm the same control-flow gap in MetaPluginSDK.

**Impact and conditions.** Ordinary transient RPC failure can block later large writes to that key and temporarily lock its upload deposit—up to approximately 13.19 ALGO for a full-size draft with a maximum-length name. This is recoverable, affects that owner/key, and does not expose funds to an outsider. Recovery currently requires lower-level box knowledge. Small writes remain possible; revocation or persistent connectivity loss can separately prevent cleanup as documented.

**Evidence.** `ALG-03` in [the LocalNet tests](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/tests/meta-audit.e2e.spec.ts:117) and [SDK tests](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/audit.test.ts:19). The chain reproduction injects the failure only after actual confirmation; it does not assume that every transport error means success.

**Recommended fix.** Make upload sessions explicit or attach owner, key, upload ID, transaction identifiers, and phase to a structured error. Put start inside outcome reconciliation, inspect the matching draft before cancellation/resume, and provide a supported lookup/cancel/resume helper. On an uncertain commit, inspect the published revision/draft rather than reporting a definite failed publication. Do not blindly cancel a different session or treat elapsed time as proof that a send failed.

**Regression test.** Simulate response loss after confirmed begin, append, and commit in both SDKs. Verify that users can identify and recover the same session, that a confirmed publication is reported accurately, and that retries do not cancel unrelated drafts.

## Design and operational risks

**OBS-01 — retained rooted-data fees.** [The docs](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/docs/meta.md:30) explicitly retain charging full storage cost on every `addData`, including replacements. [The implementation](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/smart_contracts/meta/contract.algo.ts:266) collects that amount and replaces the box; deletion refunds only one current allocation. The reproduction writes the same `audit-mbr/value` value twice and deletes it: minimum balance returns to its prior level but 24,100 microALGO remains as surplus. There is no user withdrawal route. A delegate granted repeated rooted-data writes can deliberately spend this fee repeatedly; escrow allowances/cooldowns bound that exposure only when configured. This is an explicit compatibility tradeoff. Present it as a nonrefundable replacement charge in permission/cost UI; prefer new plain records for frequent edits. Changing it requires an explicit compatibility decision.

**Draft contention and visibility.** A single draft per owner/key, public draft bytes, and no automatic expiry are documented choices. Authorized writers sharing a key can interfere with each other's upload; a write-capable delegate is not confined to its own upload session. Revocation prevents further authorized calls but does not erase a draft. The owner needs a remaining cancellation path.

**Grant composition.** `MetaPluginSDK.set()` grants inline and all four upload selectors. Each chunk group is a separate wallet execution; cooldowns, execution-key requirements, and allowances must support that sequence. A narrowly scoped deployment does not negate another broader deployment already granted to the same caller. A selected key permits replacing its entire opaque value. Scope validation does not validate JSON semantics.

**Legacy trust.** Rooted metadata still uses a 16-byte address prefix; no practical targeted collision was established. Type registration remains permissionless and costs 100 ALGO. Numeric type IDs require deployment coordination, and a type label does not independently prove leaf schema conformance. Verified reads prove membership of the supplied leaf, not that the separately stored metadata was committed to the tree.

**Public reads and rendering.** Foreign reads expose all registry boxes, including drafts; family writes remain disabled. The JSON schemas/parsers constrain presentation shapes and return `undefined` on malformed records. They do not implement image fetching, cycle handling, URI content verification, QR scanability, or renderer limits. Those consumer responsibilities are documented and were not tested here.

## Hardening opportunities

- `newMetaPlugin` accepts some immutable scopes that cannot address any supported write, for example a namespace longer than 29 UTF-8 bytes. Validate the intended record/root operations before paying to deploy/install, while retaining valid legacy-only scopes where applicable. See [scope validation](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/records.ts:96) and [record limits](/Users/kylebreeding/akita/akita-sc/projects/akita-sc/smart_contracts/meta/constants.ts:72).
- [MetaSDK.readRecord](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/index.ts:537) retries header revision conflicts, but a deletion between the first header read and the raw-box fetch throws the box-fetch error immediately. Treat a missing box in that interval as a retryable read race; preserve other RPC errors.
- [The error table](/Users/kylebreeding/akita/akita-sc/projects/akita-sdk/src/meta/errors.ts:21) still describes 32-byte data keys and 31-byte root names, and lacks the new record/upload/scope errors. Align messages with the actual 15-byte legacy key, 27-byte root, and combined record-name constraints.
- The generic legacy numeric encoder accepts truncating/wrapping values, and hexadecimal parsing is permissive. Add explicit input-domain validation when designing the versioned encoder, with compatibility tests. No new consumer exploit beyond ALG-02 was established from these behaviors.
